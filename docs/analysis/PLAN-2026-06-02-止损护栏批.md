## Workflow 编排设计（为何这样分组）

热点文件冲突分析：`src/stores/logs.js`（Q2/Q9 相关）与组件改动若并行写同一文件会产生冲突。因此：

- **阶段 A — 并行修复（文件互不相交，可安全并发）**：`Q1`(nginx/vite) · `Q4`(新增测试文件) · `Q5`(新增 CI yaml) · `Q10`(docker-compose)。各 agent 只改自己文件、不动 git。
- **阶段 A‑commit — 串行提交**：按各 agent 回报的精确文件路径，逐个 `git add <paths> && git commit`（git 操作串行化，规避索引锁竞争）。
- **阶段 B — 串行修复（logs.js/fields.js 热点）**：`Q2` → `Q9` → `Q3`，每个 agent「编辑 + 自验 + 提交」后再进入下一个，保证共享文件上每条 commit 干净。`Q3`（console 全量扫尾）放最后，避免与 Q2/Q9 改动交叠。
- **阶段 C — 收尾验证**：单独 agent 跑 `node --test` 全量 + `vite build`，回报 pass/fail。

> 所有 agent 遵守：**外科手术式改动**，只动与本 issue 直接相关的行；匹配既有风格；不顺手「改进」无关代码。

## 各 Issue 详细规格

### Q1 — Nginx 代理目标白名单堵 SSRF 🔴
**根因**：`nginx/default.conf` 用 `map $http_x_proxy_target $backend { default $http_x_proxy_target; }` 后 `proxy_pass $backend;`，把客户端可控请求头原样当上游，零白名单 → 任意内网转发（SSRF）。dev 侧 `vite.config.js` 有白名单但默认非严格（`!STRICT_PROXY_TARGETS || ALLOWED_TARGETS.has` 默认放行）。
**做法**：
- `nginx/default.conf`：用 `map` 把 **允许的命名上游**枚举为白名单（key=客户端可选标识或精确 URL，value=固定上游地址），非白名单 `default` 落到 `444`/拒绝或安全占位上游；后端地址通过环境变量/模板注入而非客户端头直拼。
- `vite.config.js`：将开发代理默认改为**严格白名单基线**（默认 `STRICT_PROXY_TARGETS=true` 语义），与生产对齐。
- 保留现有安全头/CSP 不动。
**验收**：非白名单 `X-Proxy-Target` 不再被转发；白名单目标正常代理；dev/prod 安全模型一致。
**影响文件**：`nginx/default.conf`、`vite.config.js`、必要时 `config/proxyConfig.js`
**Commit**：`fix(security): enforce server-side proxy target allowlist in nginx to close SSRF (Q1)`

### Q2 — 修复命中总数 / 字段值分布数据失真 🔴
**根因**：
- `src/stores/logs.js:69` `totalHits.value = data.length`（fetchLogs 写「截断条数」）与 `:95` `totalHits.value = data.hits.reduce(...)`（fetchHistogram 写「真实总数」）双写竞态 → 数字跳变。
- `src/stores/fields.js:123‑126`：`!hasHits` 时 `perValue = Math.floor(totalHits/len)` 给每个值均摊 → 伪造等长条。
**做法**：
- `logs.js`：新增独立状态 `loadedCount`（= `data.length`），`totalHits` 仅由 histogram 聚合权威写入；fetchLogs 不再覆写 `totalHits`。导出新字段。
- `fields.js`：`!hasHits` 时**不再均摊伪造**，标注分布未知（如 `distributionEstimated`/`status:'unknown'`，hits 置 0 或 null），保留真实计数路径不变。
- `HitsHistogram.vue` / 显示总数处：区分「共命中 N（真实）」与「已加载 M」；`FieldItem.vue`：缺真实计数时显示「分布未知」而非等长条。
- 补必要注释（呼应 D35）。
**验收**：`logsStore`/`fieldStore` 既有测试仍过；新增/调整断言覆盖「不再均摊」「totalHits 不被 fetchLogs 覆写」；UI 文案区分总数/已加载/分布未知。
**影响文件**：`src/stores/logs.js`、`src/stores/fields.js`、`src/components/HitsHistogram.vue`、`src/components/FieldItem.vue`、（如需）`src/__tests__/logsStore.test.mjs`、`src/__tests__/fieldStore.test.mjs`
**Commit**：`fix(data): separate total hits from loaded count and stop fabricating field distributions (Q2)`

### Q3 — 统一收敛约 11 处 console 调试日志 🟠
**根因**：11 处 `console.*` 散落，其中 `api/client.js:152/159` 逐请求打印后端地址（安全泄露）、`:192` 重试 warn；`stores/logs.js:67`、`stores/fields.js:75/150`、`App.vue`、`stores/query.js`、`components/LogDetail.vue`、`components/LogContextModal.vue:159`。

**验收**：`grep -rn 'console\.' src`（排除 `__tests__`、`logger.js` 内部实现）= 0；`node --test` 全过。
**影响文件**：`src/utils/logger.js`（新增）+ 上述 7 个文件
